Working with memory

3 min

A collection of programming-related articles and tutorials.

Imagine the following scenario:

“Given an array of struct sensor readings, how can you quickly copy all the data into a second array so you can process it without modifying the original?”

The most direct and efficient solution is to use memcpy. But before you reach for it, you need to understand what it actually does and where it is (and is not) safe to use.

✨ Function signature#

1

void *memcpy(void *dest, const void *src, size_t n);
  • dest: pointer to the destination buffer where the bytes will be written.
  • src: pointer to the source buffer from which the bytes will be read.
  • n: number of bytes to copy.

Returns the original dest pointer.

#include <stdio.h>
#include <string.h>

int main() {
    char src[] = "Hola mundo"; // Source string
    char dest[20];

    memcpy(dest, src, strlen(src) + 1); // +1 to copy the terminating '\0'
    printf("dest: %s\n", dest);
    return 0;
}

⚠️ Overlap warning#

If src and dest overlap, the behavior of memcpy is undefined. In those cases you must use memmove, which guarantees correct handling of overlapping regions.

// This may invoke undefined behavior:

// Safe version:
memmove(buffer + 2, buffer, 5);

void *my_memcpy(void *dest, const void *src, size_t n) {
    unsigned char *d = dest;
    const unsigned char *s = src;
    while (n--) *d++ = *s++;
    return dest;
}

Real libc implementations are heavily optimized; this is only for illustration.

📅 Best practices#

  • Ensure the destination buffer has enough space.
  • Prefer sizeof(variable) or sizeof *ptr instead of hard‑coded sizes.
  • Use it only for trivially copyable objects (POD types in C, no active invariants).
  • Validate inputs when dealing with external data.
  • Consider alignment only when doing manual optimizations.

⏱️ Performance and optimizations#

Modern memcpy implementations may use:

  • Vector (SIMD) instructions (SSE/AVX/NEON, etc.)
  • Word-sized copying with loop unrolling
  • Special CPU instructions or tuned thresholds
  • Cache prefetching heuristics

In embedded systems, a custom version might trade generality for size or deterministic timing.

❌ When NOT to use memcpy#

  • Copying C++ objects with constructors/destructors or virtual tables.
  • Managing ownership-bearing resources (dynamic memory, file handles, mutexes, etc.).
  • For string manipulation when higher-level intent (like truncation or safe concatenation) matters.
  • Between differently aligned or differently sized types without explicit reasoning.

🌟 Closing thoughts#

Although memcpy looks simple, mastering its correct usage and limits makes you a better systems programmer. It is a foundational primitive—powerful, fast, and unforgiving if misused.

“Learn to move memory, and you move the world of low-level code.”
