Logical / Arithmetic Right Shifts (c++)

6 min

Introduction#

When working with bit manipulation in C++, understanding the difference between logical and arithmetic right shifts is crucial. This post explores both types of shifts using practical C++ examples.

The Difference#

  • Logical Right Shift: Always fills the leftmost bits with zeros, regardless of the original sign bit
Logic: Fill new bits with zeros
  • Arithmetic Right Shift: Preserves the sign bit by filling the leftmost bits with the original sign bit value
Arithmetic: Fill new bits with ones

The leftmost bit is preserved, thus shifted bits are filled with ones.

🧩 Exercise: Simulating Logical and Arithmetic Shifts#

    • An integer n
    • Number of shifts k (shifts)

  2. Displays the binary representation of n (8 bits or more if number > 255)

  3. Performs both shift operations:

    • Logical right shift (unsigned >>)
    • Arithmetic right shift (preserving sign for signed integers)

  4. After each shift, displays:

    • Binary value
    • Decimal value

⚡ Implementation in C++#

The behavior of the right shift operator (>>) in C++ depends on whether the operand is signed or unsigned:

  • For unsigned integers: Always performs logical right shift
  • For signed integers: Implementation-defined, but typically performs arithmetic right shift

Protection against Undefined Behavior (UB)#

Why W is used? In the improved code:

constexpr int W = std::numeric_limits<U>::digits;

For a 32-bit unsigned int, W will be 32. So the check:

1
2
3

    if (shifts >= static_cast<unsigned>(W)) {
        shifts = W; // shifting by W yields 0 for logical, and all-sign for arithmetic if repeated, but avoid UB
    }

ensures shifts never exceeds the maximum safe amount.

Why it’s a problem#

Let’s say you have a std::int32_t (32-bit signed int). Valid shift counts are:

  • 0 to 31 ✅ defined behavior
  • 32 or more ❌ undefined behavior

If you try:

1
2

int n = 5;
int result = n >> 32;  // UB

the C++ standard says the result is undefined — meaning the compiler can do anything:

1
2
3

   + Some compilers will just leave n unchanged.
   + Others will treat the shift count modulo 32.
   + Others might generate garbage or crash.

Computaion of shifting#

Now let’s do the arithmetic and logic shiftings to the right >>. See the following code:

1
2
3

  // Compute shifts
    U logical = static_cast<U>(n) >> shifts; // logical (fills with 0s)
    S arith   = n >> shifts;                 // arithmetic (sign-propagating on most compilers)

Where static_cast<U>(n) >> shifts shifts an unsigned variable, causing the compiler to perform a logic shifting.

Logic: Fill new bits with zeros

And when S arith = n >> shifts; // arithmetic (sign-propagating)

Arithmetic: Fill new bits with ones

Conclusion#

Understanding the distinction between logical and arithmetic shifts is essential for effective bit manipulation in C++. The choice between them depends on whether you need to preserve the sign bit (arithmetic) or treat all bits equally (logical).

Notes & gotchas#

  • Arithmetic right shift on negatives: In C++ the behavior is implementation-defined for negative values, but mainstream compilers (GCC/Clang/MSVC) do sign-propagating shifts.
  • Shifts ≥ bit-width: UB in C/C++; we clamped shifts to avoid it.
  • If you want to support 64-bit paths, switch S to std::int64_t, and W will adapt automatically.

Example Scenarios#

Example 1: Positive Number#

Input: n = 8, shifts = 2

  • Original: 8 → 00000000000000000000000000001000
  • Arithmetic: 8 >> 2 = 2 → 00000000000000000000000000000010
  • Logical: 8 >> 2 = 2 → 00000000000000000000000000000010

Result: Both shifts produce the same result for positive numbers.

Example 2: Negative Number#

Input: n = -8, shifts = 2

  • Original: -8 → 11111111111111111111111111111000
  • Arithmetic: -8 >> 2 = -2 → 11111111111111111111111111111110
  • Logical: (uint32_t)(-8) >> 2 = 1073741822 → 00111111111111111111111111111110

Result: Different behaviors become apparent with negative numbers.

Key Points#

  1. Sign Preservation: Arithmetic shift preserves the sign of the number, making it useful for division by powers of 2
  2. Zero Fill: Logical shift always fills with zeros, effectively treating the number as unsigned
  3. Type Casting: In C++, you can force logical behavior by casting to unsigned types
  4. Implementation Details: The behavior of signed right shift is implementation-defined in C++, though most systems use arithmetic shift

Use Cases#

  • Arithmetic Shift: Mathematical operations, especially division by powers of 2
  • Logical Shift: Bit manipulation, extracting bit patterns, working with flags
